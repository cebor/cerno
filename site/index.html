Typed decisions from a locally hosted model.

Ask yes/no, pick-one and rubric questions. cerno reads the answer from the model’s own probability distribution over a single token — nothing to parse, no number the model was asked to invent, and nothing leaves your machine.

Three questions, one request

Three questions, 96 ms, on a 4 GB model. label_mass is how much of the model’s own probability fell on the offered letters — the one sign that it was about to write something else.

How it works

A generative model answers by writing words, and then something has to parse the words back into a decision. cerno never lets it get that far.

  1. Letter the options. Each question becomes a short prompt whose options are labelled A, B, C.
  2. Ask for one token. The model generates exactly one, in one forward pass, whatever the number of options.
  3. Read the distribution. Instead of taking the token, cerno reads P(A), P(B), P(C) from the logprobs.
  4. Fold, floor, calibrate. Tokenizer variants of a label are combined, a label that fell out of the window is bounded and flagged, and temperature scaling makes the confidences mean something.

That is where the speed comes from — one token, not a sentence — and where the probabilities come from, since they are the model’s own.

Get started

The service and the terminal front end are on crates.io; installing needs a Rust toolchain and nothing else.

ollama pull gemma4:e2b-it-qat     # once, 4.3 GB
cargo install cerno-server cerno-tui

cerno-server                      # terminal 1: the service on 127.0.0.1:3000
cerno-tui                         # terminal 2: the terminal front end

The first request takes 5–10 s while Ollama loads the model; after that it is around 150 ms. http://localhost:3000/docs is the Swagger UI.

Runs where your model runs

Every runtime gets the request fields that keep its distribution untruncated, and every host gets the same three primitives. Pick one with CERNO_HOST.
